# 没钱 No Money — 产品定位基准

> 本文是产品定位的唯一基准。任何页面、文案、功能排期与代码改动，先对照本文；
> 与本文冲突的，以本文为准。最近更新：2026-11-19。

## 0. 一句话定位

**这不是一个"算你赚多少钱"的工具。**

它是一个面向中国劳动者的**权益导航与办事平台**：把"我该做什么、我能拿什么、我去哪办"三件事，按人生阶段和用工场景拆成一条条可执行的清单与教程，每条都指到官方入口。收入、个税、社保、补偿的测算是其中一件工具，**AI 只是辅助**。

## 1. 我们服务谁

不是只服务骑手。至少包括：

- **刚出社会、第一次工作的人**：不知道入职要签什么、社保医保怎么交、公积金有什么用；
- **工厂 / 服务业 / 企业职工**：有劳动关系，但不知道自己有哪些法定权益、被侵权了怎么办；
- **灵活就业 / 新业态劳动者**：骑手、网约车司机、家政、直播、装修零工等，社保要自己缴、权益更容易漏；
- **换工作 / 失业 / 生病 / 生育 / 临近退休的人**：每个节点都有一批"必须去办"的事。

平台不预设用户懂政策、懂流程、懂找哪个部门。**默认用户零基础。**

## 2. 用户真正的三个问题

| 问题 | 平台要给的东西 |
|---|---|
| **我有什么要做？** | 按阶段的待办清单：入职、签合同、参保、公积金、个税、年检、失业登记、退休办理…… |
| **我有什么可以拿？** | 权益清单：工资、加班费、年假、工伤、失业金、生育津贴、高温补贴、经济补偿、社保补贴、培训补贴…… |
| **我去哪办？** | 官方入口：国家/省/市政务平台、APP/小程序名、窗口、电话、所需材料、办理时限 |

**一条权益 = 一个可执行动作，不是一段百科。**

## 3. 产品承诺（也是内容标准）

每条权益/办事项必须包含：

1. **一句话结论**：这件事要不要做、能拿多少（放在最前面）；
2. **谁能用**：适用身份、条件、时限；
3. **能拿多少 / 要交多少**：计算口径 + 本地数字 + 数据置信度；
4. **要什么材料**：身份证、合同、流水、诊断证明等，能照着准备；
5. **怎么办**：编号步骤，能照着做；
6. **去哪办**：可点击的官方入口（国家/省/市三级），或明确的 APP/小程序/窗口/电话；
7. **坑与时效**：常见骗局、断缴后果、仲裁时效、截止日期；
8. **依据**：法律条文/政策文件（有文号给文号，有原文给原文）；
9. **核验时间**：这条什么时候核过，过期要重核。

内容纪律：

- **不知道就标"待核实"，不编文号、不编链接、不编金额。**
- **不给死链**：入口只放能打开的站点根域名/栏目页；深链失效要能降级到搜索路径。
- **不承诺"一定能拿到"**：只给条件、路径与材料，结果由经办机构认定。
- **不代办、不代缴、不代填表**：平台只做导航和教程，最后一步由用户自己在官方入口完成。

## 4. 信息架构 v2

```
首页「我该做什么」
  ├─ 身份/阶段选择（第一次工作 / 在职 / 灵活就业 / 失业 / 生病 / 生育 / 临近退休）
  ├─ 本周待办（3–7 条，可勾选、可收藏）
  ├─ 权益速览（我这个身份能拿什么，按金额/紧急度排序）
  └─ 一个入口：继续上次没办完的事

权益地图「我能拿什么」
  ├─ 按场景：入职 / 在职 / 离职 / 工伤 / 失业 / 生育 / 退休 / 灵活就业
  ├─ 每条：条件 → 金额 → 材料 → 步骤 → 官方入口 → 坑
  └─ 相关计算器（可跳到工具箱）

办事教程「怎么弄」
  ├─ 社保参保 / 医保参保与报销 / 公积金 / 失业登记与失业金
  ├─ 生育津贴 / 工伤认定 / 退休办理 / 灵活就业补贴 / 培训补贴
  └─ 每篇：图文步骤 + 材料清单 + 省级入口对照

工具箱「算一算」（降级为工具，不是首页主叙事）
  ├─ 收入与成本 / 有效时薪
  ├─ 个税（工资薪金 / 劳务报酬 / 个体户，按身份分流）
  ├─ 养老金与社保规划
  ├─ 补偿计算 + 文书模板
  └─ 每个工具标注「适用身份」，不适用就明确说

问一问（AI 辅助）
  ├─ 回答"我这种情况该看哪条、去哪个入口"
  ├─ 解释条文与材料，不替代官方办理
  └─ 不编文号/链接，涉及认定必须提示以经办机构为准

政策与数据（支撑层）
  └─ 政策原文、数据溯源、置信度、核验日期
```

导航顺序也按这个来：**我该做什么 → 我能拿什么 → 怎么弄 → 算一算 → 问一问 → 政策与数据**。
现有「总览 / 方案对比 / 税务与养老 / 权益护航 / 政策百科」是"算钱优先"的顺序，需要重排。

### 4.1 首页默认四个入口（傻瓜式，不让人做选择题）

首页只露四个大卡，其他收进二级：

1. **我该做什么** —— 本周 3–7 条待办，勾选、进度、提醒；
2. **我能拿什么** —— 按身份/场景的权益与补贴，条件、金额/待核实；
3. **社保医保怎么办** —— 参保、断缴、报销、异地、转移；教程 + 官方入口；
4. **遇到麻烦怎么办** —— 欠薪、工伤、违法解约、押金、算法处罚；取证 → 投诉 → 仲裁 → 诉讼。

辅助入口放在四卡下方，不抢主视觉：**算一算**（收入/个税/养老/补偿）与**问一句**（AI 办事助手）。
完整内容范围、L1/L2/L3 程度标准、数据四级置信度与防编规则，见 `docs/REALITY-AND-SCOPE.md`。

## 5. 内容模型（实现用）

```ts
// 3.5.0 实际实现：src/data/rights/catalog.ts
interface RightsItem {
  id: string
  category: RightsCategory         // 入职/社保/医保/公积金/工伤/失业/生育/高温/补贴/税优/退休/维权
  intent: 'do' | 'get' | 'both'    // 要办 / 能拿 / 两者
  audience: ('all' | 'new' | 'flex')[]
  title: string                    // 用户视角的问句，如「医保断了怎么办？」
  oneLiner: string                 // 一句话结论
  whatToDo: string[]               // 第一步 / 编号步骤
  whatToGet: string[]              // 能拿什么（只写政策框架，不写具体金额）
  whereToGo: string                // 去哪办（窗口/APP/热线）
  officialUrl?: string             // 官方入口；official 必须有
  deadline?: string                // 时效/截止
  materials?: string[]             // 材料清单（P1 逐条补齐）
  caution?: string                 // 最常见的坑
  confidence: 'official' | 'derived' | 'platform' | 'unverified'
  lastVerified: string             // YYYY-MM 或 YYYY-MM-DD
  sourceTitle?: string
  guideId?: string                 // 迁移自 livingGuide 时保留
  priority: number                 // 越小越靠前
}
```

P1 再补 `stage`、`eligibility`、`amount`、`entryPoints`（国家/省/市三级）、`pitfalls`、`legalBasis`。内容源优先级：官方文件 > 官方办事指南 > 官方热线/窗口 > 权威媒体转述。**平台自采与用户实测单独标注，不混入官方口径。**

## 8. 验收标准

一个刚出社会、第一次工作的人，打开平台后：

- **3 分钟内**能回答"我现在该做什么"，并点进至少一个官方入口；
- **不用搜索**就能看到"我这个身份能拿哪些钱"，每条都有条件和材料；
- 任何一条权益都能追到**官方原文或官方入口**，且标明核验时间；
- 没核实的条目标"待核实"，不伪装成确定结论；
- 收入测算仍然准确，但它不再占据首页第一屏。

## 9. 明确不做

- 不把"月入过万"当营销点，不把收入测算当首页主叙事；
- 不做新闻/资讯聚合，不做政策解读自媒体；
- 不代办、不代缴、不代填表、不承诺办理结果；
- 不编造文号、金额、截止日期与官方链接；
- 不用 AI 替代官方入口，AI 只做解释、定位和陪跑。
